# v0.5.0-beta 진행 기록: 체력·행위자·수신 필터

2026-09-13, 진행 중인 Goal의 추가 기록. 공개 릴리스나 배포 완료 문서가 아니다. 이전 기준선은 `translation-contrast-v050.md`, 전체 상태는 `release-goal-v0.5.0-beta.md`를 함께 확인한다.

## 코드와 실제 사용 경로

- `GlossaryService.PlayerState.cs`: 완전한 한 문장의 체력 상태와 트레이드 지시만 문법으로 처리. `걔 원탭이야`는 공격 능력이 아니라 한 대 더 맞으면 죽는 상태, `내 뒤에 붙어서 트레이드해`는 과거 보고가 아니라 킬 교환 지시. 캐릭터 이름 변형에도 적용하며 지도 이름은 사람으로 보지 않는다. 질문·부정·추정·인용·추가 절이 있는 원문을 잘라 이 규칙에 억지로 맞추지 않는다. 구체적인 1HP를 만들어내지 않는다.
- 복합 위치 `B main`, `C long` 등을 전체 용어로 전달하고 한국어 `B 사이트`는 영어 `B Site`로 정규화. 기존 `low` 정의를 문맥 설명으로 실제 프롬프트에 포함. 무기 소유자와 체력이 낮은 별도 인원을 혼동하지 않도록 영어 `one has … the other is low`에만 역할 안내를 추가했다. 같은 안내를 KO/JP에도 적용한 실험은 작은 모델의 인원 보존을 악화시켜 되돌렸다.
- 사전의 `one shot → 한 대면 죽음`이 `죽음시켰다` 같은 명사형 오류를 유도했다. 현재 `한 방`과 상태/공격을 구분하는 관련 용어 설명을 사용한다. 이것도 완전한 해결은 아니며 일부 수신에서는 여전히 ‘한 방 맞았다’로 바뀐다. `풀피였어·풀피여도`도 full HP 용어와 연결하도록 활용형을 보완했다.
- 브리핑 분류가 KO/JP 원탭·풀피 문장을 Noise로 보던 누락을 수정. 풀피리/원탑/ワンショットバー 등 부분 문자열 오탐 대조군도 추가했다.
- **수신 필터의 절 추출을 제거했다.** 종전에는 조건이나 정정 절을 버리고 최대 세 절을 `/`로 이어붙였다. 이제 게임 관련 메시지를 채택하면 본문 전체와 구두점을 보존한다. 단독 무관한 욕설은 여전히 숨길 수 있지만 콜과 섞인 감정 표현까지 남을 수 있다. 한국어/영어 README에 동작을 명시했다.
- 인원→장소 오역에서 `두 곳`을 `두 명`으로 인정하지 않도록 장소 수량을 분리. `one shot/한 방`은 공격 횟수이지 적 한 명이 아니다. 문장에 one shot이 있다는 이유로 모든 인원 검사를 끄던 조건도 없애고, 해당 수사 토큰만 제외한다. `Two mid, one shot → Three mid, one shot`은 계속 실패해야 한다.

## 기본 엔진 준비 비용과 호환성

실제 Hybrid 번역 경로는 검증된 규칙 또는 선택한 AI만 사용하며 자유 문장 Lite fallback은 이미 꺼져 있었다. 그러나 UI/가이드/주기 유지/호환성 검사는 여전히 Lite를 요구했다.

- `TranslationEnginePolicy`: Hybrid/Ollama는 선택한 AI, Lite 단독은 Lite가 필요하다. Lite만 설치되어 있는데 Hybrid 준비 완료로 판단하던 오류 수정.
- 기본 구성 설치에서 Lite 설치·예열을 빼고 Hy-MT2 → Paddle OCR 두 단계로 변경. 자동 복구/주기 Lite 유지/패널 표시도 실제 선택한 엔진 기준. 이미 설치된 Lite나 모델 파일을 지우지는 않는다.
- 가이드는 고정된 기본 1.8B가 아니라 현재 선택한 모델의 준비 여부와 다운로드 크기를 표시한다. ‘권장 구성 설치·적용’은 여전히 명시적 권장값 재설정 기능이며 README에서 경고한다.
- Hybrid 호환성 검사는 실제 사용 AI에 두 문장을 보낸다. 사용하지 않는 Lite가 실패해 3/4로 표시되던 잘못된 구성을 제거했다. 이 두 문장 통과는 번역 정답률이나 전체 품질 보장이 아니다.
- 앱/README/사이트의 ‘AI 실패 시 Lite 자동 대체’ 안내를 실제 정책에 맞췄다. 홈페이지 운영 배포와 버전 동기화는 아직 남아 있다.
- 관련 자동 테스트를 포함해 **592/592 통과**. 현재 DLL SHA256 `4A5A25E5B5C200D5F6470E16C4C4A0DB152283CCD00D5A69FD93A231EB689785`.

## 실제 번역 증거

모든 폴더는 `artifacts/quality-v050/` 아래. A=의미 보존, W=어색/모호, E=오역, X=예외/차단. 내부 validator PASS를 수동 A로 간주하지 않는다. 초기 모델 적재/다른 작업 부하가 섞일 수 있어 이 소규모 P50을 게임 중 속도 보장으로 쓰지 않는다.

|---|---:|---|---|
| player-state-refined | 12 | 9/3/0/0 | 10/2/0/0 |
| player-state-variants-refined | 16 | 12/3/0/1 | 12/3/1/0 |
| health-context-revised | 4 | 1/3/0/0 | 2/1/1/0 |
| health-intent-revised | 16 | 4/5/4/3 | 9/2/3/2 |

위 revised 세 검사는 단일 공격 횟수 오탐 수정 **전** 587-test 빌드이며 현재 592-test DLL 결과로 표시하면 안 된다. 각 폴더의 meta에 DLL/표본 해시를 보존한다. 초기 full-health-disambiguation, health-filter-final도 실패 증거/판정과 함께 보존했다. 이름에 final이 있어도 릴리스 최종 통과라는 뜻이 아니다.

- `health-intent-v050.tsv`는 무기 공격 가능 질문, 내가 당한 원탭, 잘못 알았던 체력, 풀피여도 피킹 금지라는 새 대조군이다. 이를 보고 후속 수정했으므로 이제는 미공개 held-out이 아니라 회귀 데이터다.
- `health-intent-revised/rejections-raw7.jsonl`: 405 수신 원시 출력은 ‘이 총으로 체력 가득인 적을 한 방에 죽일 수 있나?’로 정상이지만 인원 검사에서 `[1]`이 추가되어 차단됐음을 확인. 검사 전체를 느슨하게 하지 않고 단일 공격 수사를 제외하도록 수정했다.
- 앞선 player-state-context(96), compound-site-contrast(64), player-state-final(96), player-state-variants(32)와 중간 실험은 별도 단계다. 단계별 표본 수를 고유 미공개 문장 수처럼 더해 홍보하지 않는다. 모든 중간 폴더가 전수 수동 판정 완료된 것은 아니다.
- `Run-TranslationQuality.ps1`은 `FamilyIds`와 `ReceiveFilterMode`를 지원한다. 기본 All은 모델 품질 비교, Briefing/Strict는 실제 수신 필터도 실행. source와 translationInput, filterKeep/reason, 필터 모드와 가족 ID를 기록하여 생략/절 손실을 숨기지 않는다. OCR 인식 자체를 포함한 검사는 아니다.

## 현재 남은 오역과 다음 검증

1. 592 빌드 `player-filter-regression` 전체320×2 및 `single-hit-count-fixed` 405 재검사를 완료했다. baseline `prompt-layout-regression` 대비 변경 출력 1.8B13건/7B12건을 모두 직접 판정하고 Merge-TranslationReview를 실행했다. 동일 원문·목표·출력·오류만 기존 판정을 상속했다.
2. 7B 404 EN 수신/407 EN 수신: 체력 취약 상태가 과거에 맞은 행동으로 변함. 1.8B 406 JP: 공격 결과 대신 one-shot 상태로 만들었다는 모호성. 현재 사전만으로 전부 고쳐졌다고 주장하지 말 것.
3. 408: 1.8B EN/JP, 7B EN/JP 수신에서 무기 소유자·양보 조건·명령형 손실. 1.8B 308 송신의 부정 보류도 남는다. 이전 넓은 표본의 감사·모욕·계획·화자 오류 역시 미해결 기록을 유지한다.
4. 추가 코퍼스 전체, 실제 OCR 안정 부하/새 설치, 앱 실행 UI 경로, 패키지·공개 Lite 모델·GitHub 및 서버 배포를 이어갈 것. 서버 전용 권한은 설치 완료이며 추가 사용자 등록 대기가 아니다.

두 모델의 `single-hit-count-fixed` 405 송신/수신 8건도 모두 A. 실제 Briefing 수신 필터에서 filterKeep=true, translationInput 원문 전체 보존, 이전에 막혔던 ‘한 방에 죽일 수 있나?’가 정상 반환된 것까지 확인했다. 이 한 질문의 네 방향이지 여덟 개의 독립 상황이 아니다.

현재 모든 모델 검사 프로세스와 해당 격리 모델 세션은 종료되었다. 앱 코드/README/사이트 변경은 로컬 작업 트리에만 있고 앱 패키지·GitHub·운영 서버는 아직 갱신하지 않았다. 전체 Goal은 ACTIVE, 외부 권한 대기로 막힌 상황은 아니다.
