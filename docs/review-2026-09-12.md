# Valtrans 코드·실행 리뷰 — 2026-09-12

기준: 현재 작업 트리 `v0.4.0-beta`. 최신 `NEXT_AGENT_HANDOFF.md`의 2026-09-11 실게임 피드백과 완료·미검증 항목을 우선 참고했다.

## 결론

모델 교체보다 **없는 정보를 추가하는 번역의 차단, 규칙의 의미 손실 수정, 실제 실행 경로를 검증하는 테스트**가 먼저다. 현재 Hy-MT2 1.8B에서도 `B → B 헤븐 2명`을 직접 재현했다. OCR이 숫자와 Heaven을 잘못 읽어야만 생기는 문제가 아니다.

156개 단위 테스트와 Arena 화면 캡처 테스트 6개가 통과해도 아래 결함은 남는다. 기존 테스트의 가치는 있으나 실제 사용자 설정·문장 변형 전체를 보증하지 않는다.

이번 작업은 리뷰다. 제품 코드, README, 사이트, 버전, 배포 파일은 수정하지 않았다. 진단 스크립트·결과는 Git 제외 경로 `artifacts/review-20260912/`에만 생성했다. 기존 사용자 변경사항은 보존했다.

## 발견 사항

### R1 · P1 — 의미 검증이 없는 정보를 통과시키고 정상 번역을 거부함

근거: `Services/CriticalFactValidator.cs:17–75`, `Services/TranslationFactGuard.cs`.

검증기는 숫자·위치가 하나라도 있는지만 주로 검사하며 원문과 결과의 실제 값, 추가된 사실, 대상과 수의 대응을 비교하지 않는다. 숫자 정규식은 one/two/二 등을 매칭하지만 변환은 `int.TryParse`뿐이다. `\b` 경계로 `2명`, `2人`, 붙여 쓴 일본어 부정·추측도 누락된다.

검증기에 직접 넣은 결과:

| 원문 | 검사 대상 결과 | 현재 판정 |
|---|---|---|
| B Main 2 | A Heaven 3 | PASS — 값 변경 |
| B Main | B Heaven 2 | PASS — 위치 변경·인원 추가; FactGuard도 그대로 반환 |
| 右に敵はいない | 오른쪽 적 있음 | PASS — 부정 반전; FactGuard도 그대로 반환 |
| たぶん右に二人 | 오른쪽 2명 | PASS — 추측 누락; FactGuard도 그대로 반환 |
| 2 B Heaven | B 헤븐 2명 | COUNT_MISSING — 올바른 번역 거부 |

현재 번역 서비스 실제 호출에서는 `B → B 헤븐 2명`(142ms), `B main → B 메인 1명`(188ms), `):B → B 헤븐 2명`(7,897ms)이 나왔다. 첫 호출 시간에는 초기 준비 영향이 있을 수 있다. 단일 실행 관찰이며 일정한 재현율·일반 성능 수치로 해석하지 않는다.

**권장 수정:** 언어별 위치·수량·부정·불확실성을 같은 표현으로 정규화하고, 누락뿐 아니라 추가·변경과 관계도 검사한다. 짧고 불완전한 원문에 숫자·세부 위치를 보충하지 않는다. 프롬프트 예시 편향은 후보 원인이지만 프롬프트 제거 비교실험 전 확정하지 않는다.

### R2 · P1 — 재검증까지 실패한 결과도 오버레이에 표시함

근거: `MainWindow.xaml.cs:2956–3007` (`ProcessIncomingLineAsync`).

검사 실패 시 한 번 재번역한 뒤, 다시 실패해도 `_overlay?.AddTranslation(...)`을 호출한다. `validation.Passed`는 캐시 저장 여부만 제어한다. 화면은 완료를 표시하고 Trace만 `validation_failed`가 된다. 안전 브리핑 반환 경로도 최종 실패 차단이 없다.

**권장 수정:** 최종 의미 검사 통과를 표시의 필수 조건으로 만든다. 실패는 추정 번역 대신 짧은 생략 이유로 처리한다. 규칙·캐시·모델 모두 같은 최종 조건을 거쳐야 한다. 먼저 R1의 거짓 실패를 고쳐 정상 채팅까지 사라지는 회귀를 방지한다.

### R3 · P1 — 사전 규칙이 복합 지시의 뒷부분을 버림

근거: `Services/GlossaryService.cs:595–614`, `Services/TranslatorService.cs:46–51`, `Services/BriefingTranslationGuard.cs`.

한국어 이동 패턴의 끝 `.*$`가 다음 지시까지 소비한다. 실제 서비스 호출:

`B로 가자 말고 A로 가자 → don't · B · rotate`

목적지 A가 없어졌지만 검증을 통과한다. 단순 부정어 붙이기는 원래의 지시 관계를 복구하지 못한다. 규칙 선행 반환은 뒤의 TranslationFactGuard도 거치지 않는다.

**권장 수정:** 규칙은 문장 전체가 단일 콜일 때만 사용한다. “말고/대신/아직/아마”가 붙은 복합문은 관계를 보존하는 번역 경로로 보내고, 부정어를 앞에 붙여 수리하지 않는다. 사전 확장 전에 과매칭 회귀 테스트를 추가한다.

### R4 · P1 — Fast/Hybrid에서 전체 채팅 합의를 Windows OCR로 수행할 수 있음

근거: `MainWindow.xaml.cs:2507–2543`.

후속 처리 조건이 `!paddle`이어서 Fast/Hybrid도 들어간다. 전체 채팅 모드와 합의 조건을 만족하면 확인 프레임을 선택 엔진이 아니라 Windows `_ocr.ReadDetailedAsync` 또는 `_ocr.ReadDualAsync`로 읽는다. 일본어 인식 차이나 언어팩 상태가 영향을 줄 수 있고 추가 인식 비용이 생긴다.

**코드 경로 확인, 해당 실사용 조합의 실행 재현은 미완료.** 이번 Arena 설정은 두 프레임 합의를 끄므로 이 문제를 검증하지 않는다.

**권장 수정:** 엔진 공통 인터페이스로 확인 프레임을 처리하고 품질 점수 척도도 통일한다. 선택하지 않은 엔진으로 넘어가는 동작은 명시적 정책으로만 허용한다. Fast/Hybrid + 전체 채팅 + 합의 켬을 별도 E2E로 추가한다.

### R5 · P2 — 캐시가 다른 문장과 변경 전 설정의 결과를 재사용함

근거: `Services/TranslationCacheService.cs:30–34`.

모든 공백을 없애므로 `now here`와 `nowhere`가 같은 키다. 직접 호출로 다른 문장의 캐시 적중을 확인했다. 모델·서버 지역·사용자 사전 변경 후에도 기존 결과가 적중했다. 현재 키에는 게임·목표 언어·스타일·원문만 있다.

**권장 수정:** 공백을 삭제하지 말고 연속 공백만 정리한다. 번역에 영향을 주는 설정의 revision/fingerprint를 포함하거나 변경 시 무효화한다. OCR raw를 키에 무조건 추가하는 것보다 의미 보존과 설정 변경 반영을 우선한다.

### R6 · P2 — 현재 지연 지표와 E2E PASS가 실제 체감 품질을 충분히 설명하지 못함

근거: `Services/MessageTraceService.cs:40–49,118–123`, `MainWindow.TestMode.cs:21–34,251–258`, `MainWindow.xaml.cs:4067`.

`TotalMs`는 캡처·OCR·합의·번역 시간 합이다. 화면 등장부터 폴링까지의 대기, 큐 대기, 전체 안정화 대기, 실제 UI 표시 완료를 포함하는 종단간 시계가 아니다. Trace 시작의 CaptureTimestampUtc도 실제 캡처 시각과 동일하지 않다.

이번 Windows 보고값은 233/103.4/68.3ms, Fast는 4,192/1,946.4/2,317.7ms였다. **서로 다른 시나리오이며 테스트 설정도 실제 기본 설정과 다르므로 엔진 우열·게임 지연 비교에 쓰지 않는다.** Fast 결과도 입력 등장부터 오버레이가 눈에 보일 때까지의 시간이 아니다.

테스트 모드는 간격 600ms, 안정화 0, 두 프레임 합의 끔, 이중 영역 끔, 전체 채팅 필터를 사용한다. Hybrid 테스트는 문서대로 FastOnly여서 VL fallback이 검증되지 않는다. 케이스 PASS는 허용 번역 문자열 비교이며 최종 검증 성공·실제 오버레이 가시성을 별도로 요구하지 않는다.

**권장 수정:** 통제된 Arena에서는 입력 표시 시점→오버레이 표시 완료를 측정하고, 실게임은 첫 감지 시점부터 측정한다. queue/모델 준비/재시도/버린 OCR 후보 비용을 따로 남긴다. p50뿐 아니라 p95, 누락률, 잘못된 표시율을 비교한다. 기존 smoke는 유지하면서 production 설정 프로필을 추가한다.

### R7 · P1 — 실패한 테스트·빌드가 성공 또는 이전 배포물로 이어질 수 있음

근거: `scripts/test.ps1:8–10,31–32` 및 마지막 PASS 출력, `scripts/Package-Release.ps1:10–14`.

`dotnet test` 종료 코드를 확인하지 않고 PASS를 출력한다. 격리된 함수 대체로 exit code 7을 주입했는데 `test.ps1 [Unit]: PASS`가 출력됐다. 이는 실제 156개 테스트가 실패했다는 뜻이 아니라 **실패 전파 장치가 없다는 재현**이다.

배포 스크립트도 `dotnet publish` 종료 코드를 확인하지 않고 기존 `publish/Valtrans.exe`의 존재로 성공을 판단한다. 이전 실행 파일이 남아 있으면 빌드 실패 후 그 파일을 다시 압축할 수 있다. 배포 동작은 실제 실행하지 않았으며 이 부분은 정적 확인이다. Full의 baseline 자기 비교는 도구 점검이지 이전 버전 대비 회귀 판정이 아니다.

**권장 수정:** 모든 외부 실행 종료 코드 실패를 즉시 전달하고, 배포는 새로운 staging 폴더에서 성공한 산출물만 패키징한다. exe 버전·커밋·생성 시각·SHA256을 manifest에 기록한다. 해시는 복사 동일성을 보증할 뿐 최신 소스 반영까지 보증하지 않는다.

### R8 · P2 — 송신 번역이 늦게 끝나면 바뀐 입력 상태를 덮을 위험

근거: `MainWindow.xaml.cs:815–842`, `Services/KeyboardReplacementService.cs:37–56`.

번역 전에는 게임 전경을 확인하지만 번역 완료 후 입력 교체 직전에는 사용자 새 입력·포커스 변경을 다시 확인하지 않는다. SetForegroundWindow의 성공 여부도 검사하지 않고 Ctrl+A/V를 보낸다. 번역 도중 사용자가 다른 문장을 썼거나 채팅을 닫았을 때 잘못된 입력 동작 가능성이 있다.

**코드상 위험 확인, 실제 게임 입력 재현은 수행하지 않음.** 자동으로 Enter를 누르는 경로는 아니므로 자동 전송 문제라고 표현하지 않는다.

**권장 수정:** 완료 직전에 대상 창·입력 세션을 검증하고 변경·포커스 이탈 시 취소한다. 지연 중 새 텍스트를 무조건 덮어쓰지 않는다. 클립보드 복사 성공도 sequence 변화 등으로 확인한다.

## 최신 인수인계 문서의 가설 정정

- 2.4초는 **최소 대기 시간이 아니다**. `Task.WhenAny`로 번역이 끝나면 먼저 반환한다. 규칙 선행 반환도 이미 존재한다.
- 전체 채팅의 4초 조건을 모든 메시지에 강제되는 지연으로 일반화하면 안 된다.
- `B rush`는 현재 규칙에서 즉시 `B 러시`로 처리된다. 신규 규칙이 없다는 전제로 수정하면 중복 작업이다.
- `2BHeaven → 2 B Heaven`은 원문에 이미 있는 사실을 분리한다. 이것만으로 `B → B 헤븐 2명`의 원인이라고 할 수 없으며 현재 서비스 재현은 모델 경로에서 추가되는 사례를 보여준다.
- Windows 일본어 약 22pt 관찰은 해당 시나리오 조건의 결과다. 모든 화면·글꼴·배율에 공통인 절대 한계로 홍보하지 않는다.
- 비16:9 영역 보정, Hybrid VL fallback은 기존 문서대로 실게임 확인이 남아 있다. 이미 완료한 DPI·최신 줄 크롭 개선을 미구현으로 취급하지 않는다.

## 권장 작업 순서와 완료 기준

1. **재현 고정 및 게이트 수정:** R7을 막고 이번 예문들을 회귀 테스트로 등록. 잘못된 실제 결과에 expected를 맞추지 않는다.
2. **의미 정확성:** R1→R3→R2. 숫자·위치 추가, 부정 반전, 불확실성 삭제, 복합 지시 손실을 송수신 공통으로 검증. `B`에는 헤븐·인원을 추가하지 않는다.
3. **캐시·송신 안전:** R5/R8. 설정 변경·문장 공백 충돌·번역 중 새 입력·alt-tab을 검증한다.
